# Plan: Bot walls
Design: docs/design/bot-walls.md
Risk paths: none — no task touches a `risk_paths` file
Diff estimate: 100

Order: the acceptance tests first; then the `blocked` count in the summary, which amends the
locked tests that pin the summary line; then the blocked verdict and the probe that sets it;
then the docs.

Rules for every task:
- A 429, a 5xx and every other `UNVERIFIABLE` reason behave as today. Only a final 401, 403 or
  999 triggers the probe.
- The text report changes only by the `blocked` count and by `BLOCKED` entries under
  `--strict`.
- Only `src/apply.rs` writes files (fitness rule). Tests never hit the real network.
- Existing acceptance tests are locked. New ones live in `tests/acceptance/blocked.rs`. A locked
  file changes only in the task that names it under `Amends:`. The orchestrator opens it with
  `whittle-gates amend` before the builder starts, and the change only adds the `blocked`
  count.
- No new dependency, config key or flag.

### T1: Acceptance tests
- Files: tests/acceptance/blocked.rs (new), tests/acceptance/main.rs
- Amends: tests/acceptance/main.rs (adds `mod blocked;`, the design's Details)
- Interfaces: none. Use tests/acceptance/support.rs as it is:
  - `World`, `Routes::fixed` / `fixed_re` (the first matching route wins; unmatched paths
    answer 404), `status`, `redirect`, `set_delay`;
  - `Settings.timeout_ms` and `Settings.no_soft404_hosts`;
  - `w.log.all()` / `hits()`, and `is_probe` for the 24-character token;
  - `Out::entries`, `entry`, `summary_line`, `assert_code`.

  Don't use `Summary` / `assert_summary`: until T2 it has no `blocked` field. Compare the
  summary line as a string. Check a count with `contains(", blocked 1, ")`. Parse JSON with
  `serde_json`.
- Test: one test per scenario, `blocked_s1_…` to `blocked_s8_…`, each `#[ignore = "pending: S<n>"]`.
  - The probe checks (S1, S5, S7) count requests whose path starts with the folder (`/wall/`,
    `/q/`) and whose last segment passes `is_probe`. S1 and S7 require exactly one such
    request.
  - S6 routes `fixed("/w/page", status(403))` before
    `fixed_re("^/w/.+", status(403).set_delay(1s))`. It also asserts that M received a request
    under `/w/` whose last segment passes `is_probe`, so it can't pass on a build that never
    probes.
  - S8 compares `post.md`'s bytes before and after. The same `--strict --apply` run also asserts
    that the entry for `M/wall/page` is `BLOCKED 403`, so the unchanged file is the result of a
    blocked finding reaching `--apply`.
- Covers: S1, S2, S3, S4, S5, S6, S7, S8
- Commit: Add acceptance tests for bot walls

### T3: Classify bot walls as blocked
- Files: src/check.rs, src/lib.rs, src/report.rs
- Interfaces:
  - Consumes `Summary.blocked` (T2) and `Probes::probe(&self, fetcher, url) -> Arc<ProbeResult>`
    as it is today.
  - Produces `Verdict::Blocked { status: u16 }`.
  - check.rs: in `check_one`, after the final `classify`, when the outcome is `Ok(fetched)`,
    the verdict is `Unverifiable` and the last hop's status is 401, 403 or 999, call
    `probes.probe(fetcher, &last.url)`. `ProbeResult::Answered` with the same status gives
    `Blocked { status }`; anything else keeps the verdict. Don't look at `host.soft404`.
  - lib.rs:
    - `check_pages`: `Blocked` gets `Fix::None`, and the summary counts it into
      `summary.blocked`, not `unverifiable`.
    - `run`: drop `Blocked` findings unless `args.strict`, before `apply::apply` and before
      the report.
    - `exit_code`: `Blocked` counts only under `strict`, like `Unverifiable`.
    - the `--strict` doc comment (src/lib.rs:86, shown by `--help`) adds that it also lists
      links on hosts that block rotguard.
  - report.rs:
    - `describe` gives `BLOCKED <status>` with no detail.
    - `rows` gives class `"blocked"`, an empty chain, reason `"<status>"`, no `final_url` and
      no fix. Make `Row.reason` an `Option<Cow<'a, str>>` so a row can own the status string.
- Test: unit tests for the new `check_one` branch with wiremock, as the existing check.rs tests
  do. A same-status probe gives `Blocked`. A 404 probe, and a 429, stay `Unverifiable`. Add a
  `blocked` row to the report.rs text and JSON unit tests. Un-pends S1, S3, S4, S5, S6, S7, S8.
- Covers: R1, R2, R3, R4, R6, S1, S3, S4, S5, S6, S7, S8
