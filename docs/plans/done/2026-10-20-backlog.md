### T2: Write the temp file safely
- Files: src/apply.rs, docs/backlog.md
- Interfaces: `write_atomic` opens `<file>.rotguard.tmp` with
  `OpenOptions::new().write(true).create_new(true)`, writes, `sync_all`s, sets permissions,
  then renames. If opening fails because the path exists, it fails without removing that path
  (it isn't ours); it removes the temp file only when it created it.
- Test: plant `post.md.rotguard.tmp` as a symlink to `victim.txt` (unix only,
  `#[cfg(unix)]`); `apply` returns an error, `victim.txt` and the symlink are unchanged, and
  `post.md` is unchanged. Fails today because `fs::write` follows the symlink.
- Covers: backlog "The temp file is opened with `fs::write`, which follows a planted
  `post.md.rotguard.tmp` symlink and overwrites an existing file; use `create_new(true)` —
  src/apply.rs:99"; backlog "No `sync_all` before the rename, which weakens R21's atomic write
  after a power loss — src/apply.rs:99"
- Commit: Write the temp file without following links
