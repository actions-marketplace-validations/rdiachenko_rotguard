# Plan: Simplify rotguard to what the site needs
Design: docs/design/simplify.md
Risk paths: src/apply.rs — T2 and T3 change `writable` and its unit tests; T7 trims its unit tests
Diff estimate: 350

Order: acceptance tests first, then the two behaviour changes (Html and bare URLs, then YAML
without the lexer), then test trimming file by file, then the link-health doc. Each behaviour
task deletes the backlog lines it settles.

Rules for every task:
- No new dependency. Only `src/apply.rs` writes files (fitness rule). Tests never hit the real
  network.
- Existing acceptance tests (tests/acceptance/*.rs) are locked; never edit them. New acceptance
  tests live in `tests/acceptance/simplify.rs`.
- Report wording doesn't change: a refused position prints `manual fix: not verbatim`
  (`Unwritable::NotVerbatim`).
- When trimming tests, delete a unit test only if it covers removed code or an acceptance test
  makes every one of its assertions; keep span and `ctx` assertions no acceptance test makes.
  Folding per-case tests into a table must keep every case.

### T1: Acceptance tests
- Files: tests/acceptance/simplify.rs, tests/acceptance/main.rs
- Interfaces: none. Uses the existing harness in tests/acceptance/support.rs (`entry`, and
  `entries_for` where a URL has two entries).
- Test: one test per scenario, named after its S-ID with a `simplify_` prefix
  (`simplify_s1_…`). S1, S2 and S3 fail today because `--apply` rewrites those positions, so
  they're marked `#[ignore = "pending: S1"]` and so on. S4, S5 and S8 describe behaviour that
  already holds and must survive the change, so they're regression guards with no pending
  marker; they pass from this commit on. `main.rs` gains only the line `mod simplify;`.
- Covers: S1, S2, S3, S4, S5, S8
- Commit: Add acceptance tests for the simplify design

  (`scan_bare`) with `verbatim: false`; spans, lines and decoded URLs stay as they are. In

- Test: flip the unit-test assertions that expect `verbatim: true` for Html and MdText links

- Also: delete the backlog line starting `- [P2] A bare URL can still end in a lone`.

### T3: Report YAML values without the lexer
- Files: src/extract.rs, src/apply.rs, docs/backlog.md
- Interfaces: in `front_matter_links`, YAML front matter no longer calls a lexer. Each URL
  value from `parse_values` becomes a link with `verbatim: false`,
  `ctx: Ctx::FrontMatter { quote: Quote::Double }`, and a span at the first occurrence of the
  URL's text in the block at or after a cursor. The cursor is a block-relative offset: it starts
  at 0 and moves to the end of each span found. A value whose text doesn't occur after the
  cursor gets the whole-block span and leaves the cursor alone (design D4). Removed:
  `lex_yaml`, `enum Line`, `is_block_indicator`, `lex_yaml_line`, the `Format::Yaml` lexer arm,
  the YAML arms of `decode`, the `doubled` parameter of `closing_quote` (YAML-only), and
  `Quote::Bare` with its `writable` arm. TOML is untouched: `lex_toml`, pairing, the decoded
  path and the sentinel `Verify` check stay.
- Test: delete the unit tests of removed code (the YAML lexer tests, the phantom-token tests
  and their helper, apply.rs `yaml_front_matter_changes_only_the_real_value`, the Bare rows of
  `decides_writability`). Keep one table test that YAML URLs, the date and each link's line are
  still extracted and every YAML link is `verbatim: false`, including a repeated URL and an
  escaped value (whole-block span). Un-pends S1; S5 and S8 stay green.
- Covers: R1, R2, R3, S1, S5, S8
- Commit: Report YAML values without the lexer
- Also: delete the backlog lines starting `- [P2] The YAML lexer still misreads some valid
  forms` and `- [P2] The front-matter sentinel check re-parses`.
